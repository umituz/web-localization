# Test Scenarios — @umituz/web-localization

This document is the **manual test playbook**. Each scenario lists exact steps, expected output, and what success/failure looks like.

> **Automated coverage:** most of the scenarios below (key sync, auto-translate,
> nested-object handling, caching, retries/aborts, CLI services, i18n setup)
> are now automated in the vitest suite under `tests/` — run `npm test`.
> This playbook remains useful for **end-to-end / release smoke testing**
> (`npm pack` → install into a fresh project → run the real `web-loc` binary)
> and for anything the unit suite cannot reach (real network, real bundlers).

**Prerequisites:**
- Node.js ≥ 18
- The package built: `npm install`
- A test directory with sample locale files

---

## Quick Setup

Create a test playground:

```bash
mkdir -p /tmp/loc-test/src/locales
cd /tmp/loc-test
npm init -y
npm install /Users/umituz/Desktop/github/umituz/apps/web/web-npm-packages/web-localization
```

# Part 1 — CLI Tests

## Scenario 1.1: First-time sync (cold start)

**Setup:**

```bash
cat > src/locales/en-US.ts <<'EOF'
export default {
  greeting: "Hello",
  farewell: "Goodbye",
  nested: {
    title: "Welcome",
    body: "Glad to see you"
  }
};
EOF

cat > src/locales/tr-TR.ts <<'EOF'
export default {
  greeting: "Merhaba"
};
EOF
```

**Action:**

```bash
npx web-loc sync --locales-dir src/locales --base-lang en-US
```

**Expected output:**

```
[i] Found 1 languages to sync with en-US.
[OK] tr-TR: +3 keys, -0 keys.
=== Sync Summary ===
Languages:  1/1 succeeded, 0 failed
Keys:       +3 added, -0 removed
```

**Expected file content** (`src/locales/tr-TR.ts`):

```ts
/**
 * Localization: tr-TR
 * Generated by @umituz/web-localization
 */

export default {
  "greeting": "Merhaba",
  "farewell": "",
  "nested": {
    "title": "",
    "body": ""
  }
};
```

**Pass criteria:**
- Exit code 0
- `tr-TR.ts` contains all 4 keys from `en-US.ts`
- Existing translation `"greeting": "Merhaba"` is preserved
- Missing translations are empty strings

**Fail indicators:**
- Non-zero exit code
- Existing translations overwritten
- File path or syntax errors

**Setup:** Same as 1.1, but make a change to `en-US.ts` (add a key), then:

**Action:**

**Expected output:**

```
[i] Found 1 languages to sync with en-US (DRY RUN).
[OK] tr-TR: +1 keys, -0 keys (dry run, not saved).
=== Sync Summary ===
Languages:  1/1 succeeded, 0 failed
Keys:       +1 added, -0 removed
[WARN] Dry run — no files were modified.
```

**Verify:** `tr-TR.ts` should be UNCHANGED (still missing `NEW_KEY`).

**Pass criteria:**
- Exit code 0
- `[WARN] Dry run` warning shown
- `tr-TR.ts` file mtime unchanged
- `cat src/locales/tr-TR.ts` shows the pre-run content

## Scenario 1.6: Translate (requires internet)

**Setup:** `en-US.ts` has 3 keys, `tr-TR.ts` has 1 of them translated.

**Action:**

```bash
npx web-loc translate --locales-dir src/locales --base-lang en-US
```

**Expected output:**

```
[i] Starting automatic translation for 1 languages.
[OK] tr-TR: translated 2 keys.
=== Translation Summary ===
Languages:    1/1 succeeded
Translated:   2 keys
Failed:       0 keys
Skipped:      1 keys
Cache:        2/1000 entries
```

**Verify:** Open `tr-TR.ts` — the previously empty strings should now contain Turkish translations.

**Pass criteria:**
- Exit code 0
- All 2 missing keys have non-empty translations
- Existing translations preserved

**Fail indicators:**
- "Translation API returned 4xx" → check your network/firewall
- Empty strings still empty → check console for 429 rate limit

# Part 2 — Programmatic API Tests

## Scenario 2.1: Basic setup + translation

```ts
// test.ts
import { GoogleTranslateStrategy } from "@umituz/web-localization";

async function main() {
  const strategy = new GoogleTranslateStrategy();
  const result = await strategy.translate({
    text: "Hello, world!",
    targetLanguage: "tr" as any,
  });
  console.log(result);
}

main();
```

**Run:** `npx tsx test.ts`

**Expected output:**

```ts
{
  originalText: 'Hello, world!',
  translatedText: 'Merhaba, dünya!',
  sourceLanguage: 'en',
  targetLanguage: 'tr',
  success: true
}
```

**Pass criteria:**
- `success: true`
- `translatedText` contains non-empty Turkish text
- `originalText` matches input

---

## Scenario 2.2: Batch translation

```ts
import { GoogleTranslateStrategy } from "@umituz/web-localization";

const strategy = new GoogleTranslateStrategy();
const requests = [
  { text: "Good morning", targetLanguage: "tr" as any },
  { text: "Good evening", targetLanguage: "tr" as any },
  { text: "Thank you", targetLanguage: "tr" as any },

const stats = await strategy.translateBatch(requests);

```

**Expected output:** `TranslationStats` with `successCount: 3`, `failureCount: 0`.

## Scenario 2.3: Object translation with progress

```ts
import { GoogleTranslateStrategy, ProgressEmitter } from "@umituz/web-localization";

const strategy = new GoogleTranslateStrategy();
const emitter = new ProgressEmitter();

emitter.on("keyTranslated", (e) => {
  console.log(`✓ ${e.from} → ${e.to}`);
});

const result = await strategy.translateObject(
  {
    source: { hello: "Hello", bye: "Goodbye" },
    target: {},
    targetLanguage: "tr" as any,
  },
  { emitter }
);

console.log("Stats:", result.successCount, "translated");
```

**Expected output:**

```
✓ Hello → Merhaba
✓ Goodbye → Hoşçakal
Stats: 2 translated
```

## Scenario 2.4: Cancellation via AbortSignal

```ts
import { GoogleTranslateStrategy, TranslationAbortedError } from "@umituz/web-localization";

const strategy = new GoogleTranslateStrategy();
const controller = new AbortController();

const promise = strategy.translateBatch(
  Array.from({ length: 100 }, (_, i) => ({
    text: `Sentence ${i}`,
    targetLanguage: "tr" as any,
  })),
  controller.signal
);

setTimeout(() => controller.abort(), 100);

try {
  await promise;
  console.log("Completed without abort (unexpected)");
} catch (err) {
  if (err instanceof TranslationAbortedError) {
    console.log("Aborted as expected");
  } else {
    throw err;
  }
}
```

**Expected output:** `Aborted as expected`.

## Scenario 2.7: i18n setup

```ts
// In a browser environment (jsdom/vitest)
import { setupI18n } from "@umituz/web-localization";

const handle = setupI18n({
  resources: {
    en: { translation: { hello: "Hello" } },
    tr: { translation: { hello: "Merhaba" } },
  },
  defaultLng: "en",
});

await handle.whenReady();
console.log("Current:", handle.getCurrentLanguage()); // "en"

await handle.changeLanguage("tr");
console.log("After:", handle.getCurrentLanguage()); // "tr"
```

**Pass criteria:**
- `whenReady()` resolves
- `changeLanguage("tr")` resolves
- `getCurrentLanguage()` returns "tr"

# Part 3 — Error Scenario Tests

## Scenario 3.1: Network failure

**Action:** Disconnect internet, then run `npx web-loc translate ...`

**Expected output:**

```
[ERR] tr-TR: Translation API returned 0
```

The `tr-TR` language shows failure, but other languages continue.

**Pass criteria:**
- Process does NOT crash entirely
- Other languages still attempted
- Exit code 1 only if ALL languages fail

## Scenario 3.2: Path traversal blocked

**Action:** Try to read `/etc/passwd` via the repository:

```ts
import { LocaleFileRepository } from "@umituz/web-localization";
const repo = new LocaleFileRepository({ projectRoot: process.cwd() });
try {
  await repo.read("../../../etc/passwd");
} catch (err) {
  console.log((err as Error).message); // "Path traversal blocked: ..."
}
```

**Pass criteria:** Throws `PathTraversalError`.

# Part 4 — Performance & Concurrency

## Scenario 4.1: Concurrent operations respect limit

```ts
import { GoogleTranslateStrategy } from "@umituz/web-localization";

const strategy = new GoogleTranslateStrategy({ maxConcurrent: 3 } as any);
const start = Date.now();

await strategy.translateBatch(
  Array.from({ length: 20 }, (_, i) => ({
    text: `Sentence ${i}`,
    targetLanguage: "tr" as any,
  }))
);

const elapsed = Date.now() - start;
// With minDelay=100ms and 20 items, should take ~700ms (20/3 chunks * 100ms)
console.log("Elapsed:", elapsed, "ms");
```

**Pass criteria:** Elapsed time scales with `minDelay * (count / concurrency)`. Not faster, not significantly slower.

---

## Scenario 4.2: Cache eviction at 1000 entries

**Setup:** Programmatically fill the cache:

```ts
const strategy = new GoogleTranslateStrategy();
for (let i = 0; i < 1500; i++) {
  await strategy.translate({ text: `unique-${i}`, targetLanguage: "tr" as any });
}
const stats = strategy.getCacheStats();
console.log(stats); // { size: 1000, maxSize: 1000 }
```

**Pass criteria:** `size` never exceeds `maxSize`. Oldest entries evicted.

# Part 5 — End-to-End Workflow

## Scenario 5.1: New project bootstrap

```bash
mkdir my-app && cd my-app
mkdir -p src/locales

# 1. Create en-US.ts as source of truth
cat > src/locales/en-US.ts <<'EOF'
export default {
  appName: "My App",
  nav: { home: "Home", about: "About" }
};
EOF

# 2. Create empty target files
for lang in tr-TR de-DE fr-FR; do
  echo "export default {};" > src/locales/$lang.ts
done

# 3. Sync structure
npx web-loc sync --locales-dir src/locales --base-lang en-US

# 4. Verify tr-TR.ts now has structure
cat src/locales/tr-TR.ts

# 5. Translate
npx web-loc translate --locales-dir src/locales --base-lang en-US

# 6. Verify all 3 languages are translated
cat src/locales/tr-TR.ts
cat src/locales/de-DE.ts
cat src/locales/fr-FR.ts
```

**Pass criteria:**
- Step 4: `tr-TR.ts` has all keys with empty strings
- Step 6: All 3 files have non-empty translated strings

1. The exact command run
2. Full stdout + stderr
3. The locale files used (or their structure)
4. Node.js version (`node --version`)
5. The package version (`npm list @umituz/web-localization`)

Open an issue with this information.
